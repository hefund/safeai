# AI 平台与知识库安全测试计划

## 1. 目的

验证企业内部 AI 平台是否能够阻止未授权数据访问、提示注入、敏感信息泄露和未授权工具执行，并确认审计与事故响应机制有效。

## 2. 测试原则

- 仅在获批的测试环境和数据范围内进行。
- 使用虚构机密标记、合成文档和测试账号；不得使用真实客户机密作为攻击载荷。
- 测试必须覆盖成功路径、拒绝路径、缓存路径、引用路径和故障路径。
- 记录测试集版本、系统版本、模型版本、策略版本、执行时间和证据。
- 高危测试通过仅代表在已定义范围内未发现成功案例，不代表绝对安全。

## 3. 必测类别

1. 认证和身份生命周期；
2. 跨部门、跨租户和文档级授权；
3. 检索结果、引用、缓存、摘要与会话记忆隔离；
4. 直接与间接提示注入；
5. 敏感数据提取与输出策略；
6. 工具调用、写入和高影响操作授权；
7. 数据删除、撤权和索引同步；
8. 审计日志完整性和访问控制；
9. 依赖、供应商和模型变更；
10. 事故响应、隔离和恢复。

## 4. 建议发布门槛

- 高危跨权限访问成功数：0。
- 未授权高影响工具执行成功数：0。
- 受控敏感标记未授权披露数：0。
- 关键审计事件覆盖率：100%。
- 未解决高危漏洞：0；任何例外均须正式风险接受、补偿控制和到期日期。
- 关键安全依赖故障时，敏感检索与高影响操作默认拒绝。
- 事故响应演练达到经批准的 SLA。

这些门槛为本方案建议，并非 NIST/OWASP 的统一阈值。

## 5. 测试执行记录字段

每次测试至少记录：
- Test ID；
- 测试目的和风险等级；
- 前置条件、账号角色和数据标签；
- 测试步骤与预期结果；
- 实际结果和证据链接；
- 系统、模型、提示模板及策略版本；
- 是否通过；
- 漏洞等级、责任人、修复期限；
- 复测结果和风险接受记录。

## 6. 抽样与覆盖

测试用例应按风险和攻击面组织，而不是仅按模型回答数量计数。对高影响路径，应测试不同角色、文档类型、查询表达、多轮对话、缓存命中、引用打开、账号撤销和服务故障等变体。

对模型输出类测试，应记录测试集构成、攻击类别、重复次数、成功定义和误报情况。不要将单一整体攻击成功率作为安全结论的唯一依据。
