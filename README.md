# 企业内部 AI 平台与知识库安全基线

> 版本：1.0.0  
> 基准日期：2026-10-27  
> 语言：简体中文  
> 适用对象：企业内部大模型平台、RAG 知识库、AI 助手，以及逐步扩展的 AI Agent

本项目提供一套面向企业内部 AI 平台与知识库的安全治理基线，包括控制清单、量化验收建议、测试计划、风险登记表和 90 天实施路线。

## 重要声明

- 本仓库是企业安全工程参考方案，不是法律意见、认证声明或 NIST/OWASP 官方标准。
- 文中标记为 **[标准/官方框架]** 的内容，表示引用已发布的标准、框架或指南；不意味着该文件对所有企业均具有法律强制力。
- 文中标记为 **[行业实践]** 的内容，是对安全社区建议的归纳。
- 文中标记为 **[本方案建议]** 的控制、SLA、KPI 和验收阈值，是建议的企业内部目标，不是 NIST 或 OWASP 规定的统一阈值。
- 企业应根据适用法律、行业监管、合同义务、数据敏感度和实际威胁模型调整本基线。
- 任何“零成功”测试门槛，都只表示在规定测试范围内未发现成功案例，不代表系统绝对安全。

## 核心原则

1. **权限由可信系统执行，而不是交给模型决定。**
2. **在内容进入模型上下文之前执行文档级授权过滤。**
3. **模型输出只是数据或操作请求，不应自动获得执行权限。**
4. **安全控制必须能被测试、审计和复现。**
5. **关键安全依赖发生故障时，对敏感数据访问和高影响操作默认拒绝。**
6. **将模型、提示模板、知识库管道、连接器和工具权限的变更纳入发布管理。**

## 快速采用

1. 复制本仓库到企业内部 GitHub/GitLab。
2. 指定业务负责人、系统负责人、数据所有者和安全负责人。
3. 盘点生产 AI 应用、模型、数据源、索引、缓存、连接器和工具。
4. 根据数据分级与业务影响确定风险等级。
5. 将 `controls/control-matrix.csv` 中的控制分配给责任人并记录证据。
6. 执行 `tests/TEST_PLAN.md`，先验证身份授权、跨部门隔离、提示注入和工具调用边界。
7. 对未通过的高危测试阻止上线，完成修复后复测。
8. 每季度复审风险登记表、测试集、例外审批和事故演练结果。

## 建议的最小上线门槛

- 生产 AI 资产和责任人登记率：100%。
- 高危跨权限访问测试：成功数为 0。
- 未授权高影响工具执行测试：成功数为 0。
- 关键审计事件覆盖率：100%。
- 未解决的高危漏洞：0 个；任何例外必须有正式风险接受、补偿控制和到期日期。
- 已完成事故响应演练，并达到企业批准的响应 SLA。

这些数值是本项目的建议内部目标。请按业务风险和测试覆盖范围解释结果，不得将其宣传为绝对安全证明。

## 维护方式

建议通过 Pull Request 修改控制项。每项变更应说明：
- 变更理由与适用场景；
- 控制责任人和证据来源；
- 验收方法及阈值；
- 是否影响现有生产系统；
- 对应的标准、指南或风险记录。
