# 安全运营、监控与事故响应

## 1. 需要监控的事件

- 未授权检索或跨租户访问被拒绝；
- 同一身份短时间内大量查询敏感内容；
- 提示注入检测或敏感输出策略触发；
- 未批准模型、连接器或工具调用；
- 高风险工具请求被拒绝或审批；
- ACL 同步延迟、删除失效超时；
- 身份、授权、策略或审计服务故障；
- 模型版本、提示模板、检索管道和工具权限变更；
- 审计日志停止、异常删除或权限配置变化。

## 2. 日志最小字段

- 时间戳、请求 ID、会话 ID；
- 用户或服务账号的稳定标识；
- 模型提供商、模型版本、提示模板版本；
- 检索文档 ID、版本、来源和授权决策；
- 工具名称、参数摘要、审批结果、执行状态；
- 策略触发、拒绝原因和告警等级；
- 响应动作、处理人、恢复时间和复盘链接。

避免将完整机密正文、访问令牌或不必要的个人敏感信息写入一般日志。必要时使用受控的取证存储并设置更严格的访问权限。

## 3. 事故响应建议流程

1. **识别与分级：** 确定影响的模型、知识库、用户、工具和数据类别。
2. **遏制：** 暂停受影响的连接器或工具；撤销凭据；必要时禁用模型路由或相关知识库。
3. **保全证据：** 保存受控审计记录、配置版本、相关请求 ID 和时间线。
4. **评估影响：** 判断是否发生未授权访问、披露、写入或外发。
5. **恢复：** 修复权限、轮换密钥、清理污染数据、验证索引和缓存状态。
6. **复测：** 重放相关测试用例，确认攻击路径已被阻断。
7. **复盘：** 记录根因、控制失效、整改负责人、期限和预防措施。
8. **通知：** 按适用法律、合同和内部流程决定是否通知客户、监管机构或受影响人员。

## 4. 建议内部响应目标

- 高危事件 5 分钟内触发告警或安全动作；
- 15 分钟内隔离受影响功能；
- 关键安全服务故障时，敏感检索和高影响工具默认拒绝；
- 每季度至少进行一次桌面或技术演练。

上述时限是本方案建议值。组织必须通过实际演练验证可达性，并根据业务影响和人员覆盖调整。
